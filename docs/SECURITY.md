# Security

Tenant isolation is enforced at the API boundary for the canonical project catalog: organization comes from the authenticated user and the PostgreSQL adapter filters by organization. Mock mode uses the deterministic demo principal. Production mode requires a bearer token, a verified Supabase JWT with `sub`, `exp` and an explicit organization claim, and membership validation in the persistence layer. Project-scoped requests are checked again by middleware before reaching handlers.

Local evidence links are HMAC signed with an absolute expiry and the S3/R2 adapter delegates expiry to presigned URLs. Storage keys reject absolute paths and traversal segments. Secret/PII redaction, provider allowlists, per-document consent, guest OTP verification, host allowlists, isolated browser contexts, file validation, CSP, rate limiting and audit events remain required controls before accepting real client data. Consent records are scoped to organization, project, document, provider and route, and expire or can be revoked.

The browser agent treats all visited content as untrusted. Destructive actions are disabled by default and sensitive actions require explicit confirmation. The current demo uses mock data and must not receive real secrets. Hosted model requests isolate external content from system instructions, use structured outputs and ask the provider not to retain the payload. Extra hosted routes and self-hosted models are opt-in and must be approved one route at a time. Retention and provider policy must still be reviewed for the deployment region and data classification.
